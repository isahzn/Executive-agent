## Project purpose
Public website for **Bantex Trading (Pvt) Ltd** — a wholesale + retail business in **Stationery & Electrical Goods**, Colombo 12. Deploys to **Vercel**. The production site is the Next.js app in `web/`. The static prototype in `Front end/` is the **design source of truth** (do NOT redesign it).

## Design direction
Professional trade-supplier voice (credible, established, approachable) — not the "premium student stationery" tone of the Inkwell prototype. Honest content only. Avoid the generic AI/SaaS tells in skills/frontend-design.

## Tech stack
Next.js (App Router) + TypeScript, plain CSS with `:root` design tokens (no Tailwind). `next/font` for **Fraunces** (display serif) + **Inter** (body), self-hosted. Static prerender; JSON-LD LocalBusiness schema in layout. `next/image` with `remotePatterns` for `images.unsplash.com`.

## Architecture decisions
- Next.js App Router + TypeScript; app lives in `web/` inside the project directory.
- Plain CSS design tokens, **not** Tailwind.
- Content static self-contained (no backend/auth for catalog + contact). Contact is via `tel:` + `mailto:` links; no fabricated forms. A SMTP enquiry endpoint may be added later (needs env secrets — not Phase 1).
- No fabricated data — no fake reviews/ratings/stats/delivery claims/hours/socials. **Exception (documented):** (a) the 3 demo products in `web/lib/catalog/seed.ts` (pen/calculator/charger with invented prices, marked `isSeedDemo: true`, editable/deletable via admin) and (b) **all 38 real hardcoded products also carry placeholder prices** (owner has not confirmed prices yet; product photos carry no prices). Product names/brands/pack sizes come from the owner's actual product photos and their packaging text — never from imagination. Replace placeholder prices via `/admin` or a seed edit once confirmed.
- **Single authoritative catalogue source (Phase 7).** `web/lib/catalog/store.ts` is the one source of truth — a file-backed JSON store (`web/data/catalog.json`, gitignored, seeded from `seed.ts`) behind a clean synchronous CRUD interface, so a real DB can be swapped in during Phase 8 without touching callers. `lib/products.ts` is a thin read accessor over it so Phases 1–6 components keep working unchanged.
- **Route-group split.** The customer-facing shell (Header/Footer/CartProvider/JSON-LD) moved into `app/(public)/layout.tsx`, and the root `app/layout.tsx` is a minimal fonts+globals shell. This gives `/admin` its own full-screen shell (no public nav/cart) while keeping all public URLs identical.
- **Order + email (Phase 8).** `web/lib/orders/` is a persistent file-backed store (`web/data/orders.json`, gitignored via `/data/`) behind the same swap-ready `OrderRepository` interface pattern as the catalogue — a real DB can replace it without touching callers. Orders are created server-side only (`createCheckoutSession`); a Stripe Checkout Session is attached once created. The webhook marks an order **paid only when `session.payment_status === 'paid'`**, idempotently (an `alreadyPaid` check re-uses the paid order on duplicate deliveries); `checkout.session.expired` marks a still-pending order failed. Owner email (nodemailer) is sent after a paid event, but **its failure never rolls back the payment** — it's recorded as `emailStatus: "failed"` and the order stays paid. Cart clearing is gated on the server-verified paid success page (`ClearCartOnConfirm`), so navigating straight to the success URL, cancelling, or a failed payment never wipes the cart. Admin order-status changes go through a guarded API that accepts only `orderStatus` — `paymentStatus` is never client-writable.
- Reveal-on-scroll uses an `html.js` gate so content stays visible for SEO/no-JS; `prefers-reduced-motion` respected.

- `next/font` fetches Google Fonts at build time (network required).
- Next.js **16.3.4** has breaking changes vs. older docs — read `web/node_modules/next/dist/docs/` before writing Next-specific code.
- **Catalogue & order persistence is not production-ready.** `web/lib/catalog/store.ts` (`web/data/catalog.json`) and `web/lib/orders/store.ts` (`web/data/orders.json`) write synchronously and re-seed from seed when missing. That works in dev, but Vercel's serverless function filesystem is read-only/ephemeral for the bundled output, so admin edits and orders created in the deployed app will be lost on cold start. A real datastore behind the same swap-ready interfaces is future work (not part of Phases 1–8). Used with a single-instance dev server it behaves correctly today.

## Handoff file

At the end of each working session, create or update `handoff.md` in the project root (`Projects/BantexTrading web/`) with these concise sections:

- **Goal** — what this session set out to do.
- **Current state** — what is done, what is not.
- **Active files** — the files touched/created.
- **Changes made** — the concrete edits.
- **Failed attempts** — blockers and what caused them (or "none").
- **Next steps** — what to do next.

It is the handoff for the next session/agent. Never invent or pad it; report what actually happened.
