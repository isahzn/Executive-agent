# Tasks / Backlog

## Purpose

Tracks tasks that need to be done but have not yet been started.

## Backlog Items

_No backlog items._

---

## Item Format

When adding to backlog:

```
## [Priority] — [Task Name]

- **Objective**: [What is the goal?]
- **Scope**: [What is included/excluded?]
- **Related Project**: [If any]
- **Estimated Effort**: [Quick | Medium | Large]
- **Priority**: [High | Medium | Low]
- **Dependencies**: [Does this depend on other tasks?]
- **Notes**: [Any additional context?]
```

---

## Priority Levels

| Priority | When to Tackle | Definition |
|----------|---|---|
| **High** | Next | Blocking other work, critical, user-requested, deadline-driven |
| **Medium** | When capacity allows | Useful, planned feature, improves experience |
| **Low** | When everything else is done | Nice-to-have, future consideration, experimental |

---

## Moving Items from Backlog to Active

When user wants to work on a backlog item:
1. Move from backlog to active.md.
2. Enter PLAN mode.
3. Build an approved plan.
4. Record in active.md.
5. Proceed with execution.

---

## Adding Items to Backlog

When new work is identified but not approved:
1. User identifies work that needs to be done.
2. Freebuff clarifies scope and effort.
3. If not approved for immediate action, add to backlog.
4. Record with priority and dependencies.

**Rule**: Backlog items are not approved for execution. They are candidates for future work.

---

## Backlog Maintenance

### Reviewing Backlog
Periodically (or when backlog is large):
1. Review all items.
2. Prioritize based on current situation.
3. Consolidate similar items.
4. Remove obsolete items (move to Recycle Bin).
5. Add context if items have become clearer.

### Pruning Backlog
If backlog gets too large (>20 items):
1. Review each item.
2. Identify items that no longer matter.
3. Move obsolete items to Recycle Bin.
4. Consolidate related items.
5. Keep only items that are genuinely planned.

### Planning from Backlog
1. User looks at backlog and says "let's do item X."
2. Freebuff loads item X from backlog.
3. Freebuff enters PLAN mode.
4. Freebuff builds plan (scope may have changed since backlog entry).
5. User approves plan.
6. Item moves to active.md.

---

## Backlog vs. Recycle Bin

- **Backlog**: Items that might be done in future, not yet approved.
- **Recycle Bin**: Items that are obsolete, historical, or might be useful later but are not planned.

If a backlog item becomes obsolete:
- Move to Recycle Bin with a note explaining why.
- Do not delete outright.

---

## Rules for Backlog Management

- **Do not overload**: Backlog should be manageable, not overwhelming.
- **Do not approve**: Items in backlog are not approved. Do not start them without approval.
- **Do prioritize**: Use priority levels to guide what to work on next.
- **Do track dependencies**: Note what items depend on other items.
- **Do clean up**: Remove obsolete items periodically.
- **Do not expand approved tasks** by pulling in backlog items. Backlog items are separate work.

---

## Backlog Growth Notes

If backlog is growing faster than tasks are completed:
- Discuss with user about capacity and priorities.
- Consider whether all items are actually necessary.
- Do not accumulate backlog indefinitely without addressing it.
